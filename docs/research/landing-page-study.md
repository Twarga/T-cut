# Landing-page reference and T-cut adaptations

Source: [CapCut’s public landing page](https://www.capcut.com/). This is website research, not a CapCut Desktop compatibility test.

## Evidence

The page was read as HTML/text and opened in Chromium at 1440 × 900. The top and a lower tools section were visually inspected. Content can change by locale, account and rollout; these observations do not certify an immutable current design.

| Observed pattern | T-cut implementation |
|---|---|
| Compact top navigation with logo left and two actions right | Original T-cut lockup, section links, theme toggle and GitHub action |
| Large centered hero; accented phrase in the heading | Centered heading with violet accent and original coming-soon copy |
| Short explanation, two main CTAs, reassurance underneath | Read the plan / View the repository; planned free/offline/account-free commitments |
| Pale atmospheric shading around the light hero | Theme-aware violet wash; both Ink/dark and Paper/light |
| Product/tool showcase below the hero | Original abstract editor illustration, visibly labeled as a concept |
| Tools grouped into numbered sections and feature cards | Six MVP cards and a progressively enhanced 0–5 phase roadmap |
| Partner logos, templates, testimonials and download/rating statistics | Omitted; no partnership/user/performance evidence exists for T-cut |
| Signup/credit promotion appeared in the observed view | Omitted; no signup, email collection, credit balance or hosted service |
| Repeated product-start actions | Useful repository/documentation/review links, not a fake app launch or download |

## Independent identity

The site reuses the recognizable information hierarchy, not CapCut’s logo, cyan palette, source code, media assets, wording, testimonials or claimed numbers. T-cut uses an original cut-T mark, violet/lime accents, self-hosted Inter/Space Grotesk and independently authored HTML/CSS/JavaScript.

The user’s “same interface” requirement still controls the eventual **desktop editor** through the screenshot-backed [fidelity contract](fidelity-contract.md). Website branding must not silently replace that requirement with a redesigned editing workflow.

## Cognitive-accessibility choices

- State availability near the hero; no visitor must read the roadmap to learn that the editor is not built.
- Show one primary action and one secondary action, with labels naming their destinations.
- Use phases 0–5 consistently; internal qualification is not an installable release.
- Keep each feature card to one heading and paragraph.
- Let users select a roadmap phase; do not autoplay or rotate it.
- Keep all six phases readable and linked when JavaScript is disabled.
- Leave the 121-frame engineering discrepancy in the Phase 0 panel and technical plan rather than the primary pitch.
- No scroll-triggered reveals that hide content, countdowns, moving marquees, or fabricated urgency.

These choices support scanning and reduce interruptions. They are not a claim of clinical ADHD treatment or a substitute for usability testing with actual readers.

## Limits

No T-cut video-editor binary exists. The illustrative preview and banners must not be described as product screenshots. Automated accessibility checks and browser interactions can verify this website; they do not prove rendering, AI capability, media compatibility or desktop behavior.
