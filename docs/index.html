Coming soon · Free and open source

A familiar video editor, planned for Linux.

T-cut is a free, open-source editor built around the workflow CapCut Desktop users already know. It is not a clone of CapCut's interface. It is planned to run offline, with no account and no subscription.

Version 0.1

What the first usable release includes

Fewer tools than CapCut. Every item below has to work end to end before v0.1 ships. No placeholder buttons.

  1. 01

    Projects and import

    • Home screen with project cards: create, open, rename, duplicate, move to trash and restore.
    • Import local video, audio and images, with rotation and duration read correctly.
    • Unsupported files are reported with the reason. Nothing fails silently.
  2. 02

    Timeline editing

    • Multiple tracks. Trim, split, move, duplicate and delete clips.
    • Undo and redo restore the exact previous project state.
  3. 03

    Titles and audio

    • Static titles with font, size, color and alignment.
    • Arabic, CJK and emoji shaped correctly from the first release.
    • Music volume with fade in and fade out, mixed into the exported file.
  4. 04

    Export and your files

    • Export a finished video with the audio mix included.
    • Project folders with readable JSON, autosave and crash recovery.
    • Relink moved media without losing edits.
Roadmap

Built in six phases

Each phase is a capability gate, not a date. No release dates are promised, because Phase 0 can still change the engine decision and everything downstream with it.

  • 0 Engine test
  • 1 Basic editor
  • 2 Smooth editing
  • 3 Creator tools
  • 4 Local AI
  • 5 Stable

Phase 0: Engine test

No public release

Nothing to use yet. This phase decides whether the foundation is sound.

  • Build a real Rust window that plays and exports known media.
  • Generate test footage with numbered frames and audio impulses at known positions.
  • Run 12 qualification checks and decode the output with an independent tool.
  • Commit to one media backend, with the reasoning written down.

The gate: a nominal four-second, 30 fps render previously produced 121 frames and 4.033333 seconds instead of 120 frames. The cause must be found and fixed, or the engine replaced. Changing the expected number to match the bug is not an acceptable outcome.

Phase 1: Basic editor

v0.1First usable release

Make and export a simple video, using a layout you already recognize.

  • Home with projects; create, open, rename, duplicate, trash and restore.
  • Import; trim, split and move across multiple tracks; undo and redo.
  • Canvas presets with position and scale; static titles; music volume and fades.
  • Autosave, crash recovery, relinking moved media, and a real export.

Deliberately excluded: transitions, keyframes, auto captions, effects and AI. They are planned for later phases and will not appear as controls that do nothing.

Phase 2: Smooth editing

v0.2

Editing stops feeling clumsy, and you can subtitle a video by hand.

  • Snapping, main-track magnet and linked clips, each a separate visible control.
  • Richer static text styling and fuller audio controls.
  • Manual captions, with SRT and VTT import and export.

Phase 3: Creator tools

v0.3

The creative jump: animation, composition and color.

  • Keyframes and easing; speed, reverse and freeze frames.
  • Transitions, masks and chroma key.
  • Color grading with curves, LUTs and scopes; animated text.
  • Screen and webcam recording; original templates.

Phase 4: Local AI

v0.4Optional

Assistance that runs on your own machine, suggests rather than overwrites, and is always optional.

  • Auto captions and translation; transcript-based editing.
  • Background removal, object tracking and auto reframe.
  • Voice cleanup, music separation and beat detection.
  • Text to speech, dubbing and upscaling.

Honest warning: each of these needs a model whose license permits redistribution and commercial use. Where those rights cannot be established, the feature ships as unavailable with the reason stated. It is not faked, and it is not quietly replaced by a cloud service.

Phase 5: Stable

v1.0

No new features. Make the existing ones trustworthy.

  • No release-blocking defect that can lose your work.
  • A published, measured list of supported media and hardware.
  • Tested installation and upgrade on the supported runtime.

A stable local editor is not a claim that every CapCut cloud service has been reproduced. Generative video, broader project interoperability, optional self-hosted sync and authorized publishing are tracked separately after v1.0, each with its own rights and infrastructure gate.

Architecture

The planned stack

Chosen to avoid rewriting solved problems, and to keep your project data independent of any single component.

Every row is a starting decision with a qualification gate, not a finished result.
LayerChoiceWhyState
Logic and state Rust 2024 Owns exact rational time, typed edit commands and undo, so correctness never depends on a widget. Decided
Desktop UI GTK4 (Rust bindings) Native Linux integration, with keyboard and screen-reader support already in place. Decided
Playback and render GStreamer / GES Twenty years of codec and audio-clock work that nobody should rewrite. Conditional
Text shaping Pango · HarfBuzz · FreeType Correct Arabic, CJK, combining marks and emoji, identical in preview and export. Decided
Project format Versioned folder, JSON snapshots and a journal Readable and recoverable. Project truth is never inside a cache or a database. Decided
Packaging Flatpak first One tested dependency set across distributions, with real portal behavior. Decided
AI Optional isolated local workers Offline, versioned and license-audited. No authority to rewrite your project. Gated

Deliberately rejected

  • A web-based desktop UI. We chose GTK for Linux integration and a direct native media path.
  • Rewriting codecs in Rust. Years of work to re-solve something already solved well.
  • A custom GPU engine. It would still not demux, decode, or drive an audio clock.
  • A database as the only project format. We chose readable snapshots and a journal; both formats still need crash-recovery testing.
Evidence policy

Every claim is labeled

A reader can tell a measurement from an intention. This page has no testimonials and no download counts, because there are no users and nothing to download yet.

Documented
Upstream documentation states the capability.
Visual
Seen in a public screenshot, with its source recorded.
Observed
An identified build was actually exercised and the result logged.
Proposed
Our own design decision, not a copy of anything.
Gate
Evidence still required before the claim may be made.

The interface research studied 28 public screenshots from several CapCut versions. They are kept separate by version rather than merged into one claim of exactness. No CapCut application was run. Before T-cut claims a verified compatibility profile, behavior has to be recorded against one pinned CapCut Desktop build.

Review the plan before the code exists

The most useful contribution right now is review. If a requirement, dependency or evidence gate looks wrong, say so today. Fixing it in a patch later costs more.
